    Fix QMIX lane-mapping regressions across Sands (delegation, spread rows, VAR/LEG LOR) + harden LaneMapping
    
    Root cause: QMIX widened editor order to 7 (MEL/OCT/QMIX/REST/ACC/VAR/LEG) and poly to 5, but several sites kept pre-QMIX indices. Fixes: (1) generators emit engine-lane spread/prob/atten/send/tap ids at editor rows via EDITOR_TO_ENGINE (Macro cv/atten/spread; East spread) - fixes 'melody row controls REST spread' mislabel; SVGs regenerated. (2) SandsTopology::owner() VAR/LEG cutoff >=4 -> >=kPolyLanes(5), guard >6 (ACC is now a delegable poly lane). (3) East owner cells editor->engine (EDITOR_TO_ENGINE_LANE_QMIX) in get/setMacroOwn/MonoMacroOwn + menu + owner light; VAR/LEG owner cells param_owner_5/6 (were 4/5, collided with ACCENT's param_owner_4 -> fixes ACCENT delegation + stray LEGATO cell); DirCell VAR/LEG vl=lane-POLY_LANES (was lane-4) -> LEG direction operates. (4) Mono DirCell lock cutoff >=POLY_LANES. (5) Poly VAR/LEG LOR store-bank vl+4 -> canonical helper (was reading QMIX's bank into VAR -> 'editing QMIX also edits LEGATO' + poly VAR/LEG edits never took). HARDENING (prevents the bug class): dsp/LaneMapping.hpp gains the single canonical lorStoreBank(editorLane)/varlegStoreBank(vl) + POLY_LANE_COUNT/EDITOR_LANE_COUNT with static_asserts on the exact banks; East lorBank/Mono bLor/MonsoonExpanderManager varleg all route through it (no more vl+magic); SandsGrid.hpp cross-header static_assert ties its lane counts to LaneMapping's so they can't diverge. Verified clean in Rack.
