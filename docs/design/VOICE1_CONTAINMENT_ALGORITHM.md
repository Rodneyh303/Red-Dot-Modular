# VOICE-1 CONTAINMENT ALGORITHM — how poly legato / rest / accent derive relative to voice 1

Rodney brief (2026-10-26): "containment in the plugin set is implemented all within voice 1.
every other voice is 'subtractive' compared to voice 1. Voices can rest when voice 1 does but
not sound when voice 1 rests. … document how the allowed note variation legato, rest and accent
for poly voices is set relative to voice 1 … for both clock/phase modes and gate mode with
subgates. The objective is so we can generalise this and ultimately connect it to the structures
generated by cantonment (including nested and multi parent structures). For this we will need to
modularise the code so we can connect it through the forest structures. So instead of all voices
being contained in voice 1 envelope it fully generalises based on cantonment patterns."

FILED in-repo on Rodney's instruction (2026-10-26) — reference doc for the containment → Cantonment-forest generalisation.

---

## 0. The one-sentence invariant

A poly voice may only ever sound INSIDE voice 1's envelope: it can only start a note at a V1
onset, it is force-closed whenever V1 rests, it can never hold past V1's next event, and in gate
mode its sounding gate is the logical AND of the V1 envelope and its own latched play/rest
decision. Everything else (pitch, rest roll, accent roll, slur roll) is the voice's OWN draw.

"Subtractive" is precise: the intersection is asymmetric. V1's envelope bounds the poly voice
from above; the poly voice can only remove time from it (its own rest draw), never add.

## 2. Who writes the decision thresholds (the sole-writer map)

The engine never reads knobs mid-draw. The controller (ModeController) is the SOLE writer of
both ends, each block, before execution:

**Mono slot (V1)** — `ModeController::updatePatternInput` (MonsoonModeController.cpp:66,
rhythmLive branch 115-137):
```
monoVoice.restProb       = currentPatternInput.restProb          // getEffectiveMonoRest (Causeway-CV modulated)
monoVoice.legatoProb     = paramManager.getLegato()
monoVoice.accentProb     = getEffectiveMonoAccent(...)           // Causeway-CV modulated
monoVoice.qmixLevel      = getEffectiveMonoQmix(...)
monoVoice.variationProb  = currentPatternInput.variationAmount
```

**Poly slots (V2..V16)** — `ModeController::updatePolyVoiceRest_` (MonsoonModeController.cpp:30-64),
called inside `postExecute_` right before `executePolyVoices` (MonsoonModeController.cpp:236-238):
```
voices[vs].restProb       = getEffectivePolyRest(i-1)
voices[vs].accentProb     = getEffectivePolyAccent(i-1)
voices[vs].qmixLevel      = getEffectivePolyQmix(i-1)
voices[vs].variationProb  = getEffectivePolyVariation(i-1)
voices[vs].legatoProb     = getEffectivePolyLegato(i-1)
```
All five are per-voice (knob + CV, clamped) — the DRAWS are the voice's own (its own LOR window
over `warpRow`), the THRESHOLDS are its own; what is NOT its own is the PERMISSION STRUCTURE
(when it may draw at all), which is entirely V1-relative (§4).

Lock note: poly REST/ACCENT/VAR/LEG/REST are Tier-V LATCH (BigFive class): under lock the
refresh is skipped and the pre-lock values hold (MonsoonModeController.cpp:43-44), with a
one-shot prime (`polyVoiceCachePrimed_`) so a locked load still populates.

## 3. Mode dispatch and the edge that drives a step

`Monsoon.cpp:976-985` composes ONE `stepEdge` per mode, fed to `RateManager::advance(Rate::Step)`:

- **Mode 0 (clock origin)**: `stepEdge = clock.sixteenthEdge` — the internal PPQN clock's 1/16 edge.
- **Mode 2 (phase origin)**: `stepEdge = phase.sixteenthEdge` — the phase ramp's 1/16 crossing
  (with jump/scrub replay, Monsoon.cpp:1047-1088).
- **Mode 1 (gate origin)**: `stepEdge = input.gate1Rise || (gate1High && stepIndex==-1)
  || (inGate && input.subGateRise) || (!inGate && input.ghostRise)` — three edge streams
  (main / ratchet / ghost, §5.3).

At each PPQN pulse (Monsoon.cpp:990-998) ALL gate states tick their pulse countdowns — mono AND
every poly voice (`gs.tickPulse()` / `gsStep.tickPulse()` per voice). At each Step edge:
`mc.executeMode(modeSelect, ...)` → the mode executor runs the mono cascade (`executeStep`),
then `postExecute_` runs the poly cascade (`executePolyVoices`) — in that order, so poly reads
the CURRENT step's mono verdict via `lastStepResult`.

## 4. The V1-relative algorithm

### 4.1 The mono cascade — `executeStep` (SequencerEngine.cpp:493-731)

V1's own decision chain. Mode-agnostic (all three executors call it):

1. **MidNote guard** (536-541): if `gs.holdRemain >= 1.f || gs.gatePulseRemain > 0` the previous
   note is still sounding → verdict `MidNote`, nothing is drawn. (Fractional-tail subtlety:
   `gatePulseRemain` keeps the guard alive through a triplet's partial last step.)
2. **Pitch**: `voicePitch(monoSlot, ...)` from `warpRow(mono, PL_MELODY)[getMelodyStep()]` and
   `PL_OCTAVE` (571-577); quantiser/q-mix source-select may substitute the external CV.
3. **Leading-edge capture** (585): `prevSlur = gs.slurForward` — the PREVIOUS note's onset
   commitment, captured before this note's cascade recomputes it. This is the leading-edge
   legato model: the connection is governed by the predecessor's commitment, never re-rolled
   at the join.
4. **Branch cascade** (in priority order):
   - `LegatoMax` (623): `legatoProb >= 0.999` → `slideMax` (forced connection, no retrigger).
   - **Rest** (628): `r_rest < voices[mono].restProb` AND not suppressed by a slur
     (`slurSuppressesRest = !generatedRestBeatsLegato && slurReachesHere`). Only taken if
     `canRest` (606): `holdRemain <= 0.0001f && !hadTail` — a fractional tail ALWAYS outranks
     rest (falls to MidNote to let the tail finish, 640-644).
   - **Legato/Tie** (646): `legatoConnects && (wasHeld || hadTail) && prevPlayedSounded` —
     committed slur AND a still-sounding predecessor AND that predecessor sounded in play
     order (the direction-correct test, 595-600). Same pitch → `Tie` (`extendHold`), else
     `Legato` (`slideNote`).
   - **NewNote** (667): fresh `triggerNote`.
5. **Accent** (673-685): on a STARTING step (`monoStarting`: NewNote, or Legato/LegatoMax from
   a dead gate) → `accented = r_accent < voices[mono].accentProb` (V1's own accent draw vs V1's
   own threshold, read at V1's OWN accent LOR step — `getAccentStep()`, SequencerEngine.cpp:990
   in the executor feeders). On Rest → false. On sustain (Tie/MidNote/connected Legato) →
   **inherit** `lastStepResult.accented`.
6. **LEAD commitment** (703-727): a starting note commits `gs.slurForward` for the NEXT edge iff
   its own legato draw fires (`r_legato_tie < legatoProb` or LegatoMax) AND its length is
   grid-aligned (`noteCanLeadLegato(nvIdx)`, NoteValues.hpp:61 — fractional lengths cannot lead).
   Tie may lead (3+ chains). MidNote/Rest never start.

### 4.2 Clock/phase mode poly derivation — `executePolyVoice` (SequencerEngine.cpp:1116-1390)

Runs per voice V2..V16 (`executePolyVoices`, 1392-1402) after every stepped mono execution.
`wasHeldPoly = wasHeldPolyPrev[i] || hadPolyTail[i]` captured BEFORE the ticks (1400).

**Stage 2 — subtractive note length.** `nvV = nvIdxForVoice(voiceIdx, input)` (1124; def 1499-1508):
the voice re-derives its note length from its OWN variation window
(`getVariationStepForVoice` — mono's cell when delegated, its own when Local-East) but then:

```cpp
return (nv > lastStepResult.nvIdx) ? nv : lastStepResult.nvIdx;   // 1507
```

NOTE_VALUES is ordered slowest→fastest, so `max()` picks the SHORTER — **a voice may release
early, never hold past V1's next event** (the header comment at 421-424 says exactly this:
"Articulation is thus SUBTRACTIVE, exactly like rest and accent").

**Onset gate — `monoGateStart`** (1128-1131): the ENTIRE poly decision structure hangs on V1's
verdict:
```cpp
monoGateStart = (lastStepResult.decision == NewNote)
             || ((decision == Legato || LegatoMax) && !wasHeldMono && !hadMonoTail);
```
Poly voices may only BEGIN a note at a V1 onset. There is no path to a fresh poly onset
anywhere else in clock mode.

**At `monoGateStart` (the whole mono gate's decision point):**
1. **Ghost placement** (1152-1163): if V1 ghosted this onset (`ghostActive`), the voice rolls its
   OWN variation draw at its own VAR step; failing it becomes a RESTED GHOST — silent,
   `participating=false`, transparent to the chain.
2. **Own rest draw** (1136-1176): `r_rest = warpRow(voice, PL_REST)[own rest LOR step]`;
   `r_rest < v.restProb` → REST: tail allowed to finish (1168), gate closed otherwise, and
   **`participating = false`** (1173) — a resting voice is not part of this chain and commits
   no slur.
3. **Play** (1178-1228): own pitch (own MEL/OCT LOR), own accent draw (1213-1215: own ACC LOR vs
   own accentProb), then the GATE TYPE follows V1's verdict:
   - V1 NewNote → `triggerNote` (fresh, 1216-1217)
   - V1 slurring AND this voice had a held predecessor → `slideNote` (real slide, 1218-1220)
   - V1 slurring but this voice had NO held gate → fresh `triggerNote` (the poly isolated-teal
     guard, 1221-1227)
4. **Rule-2 LEAD roll** (1240-1253): `participating = true`; the voice commits its OWN
   `gs.slurForward` from its OWN legato draw at its own LEG step (delegated → V1's cell by
   default, so the voice's slur pattern mirrors V1; Local-East → independent), thresholded by
   its own `legatoProb`, gated by `noteCanLeadLegato(nvV)`.

**V1 verdict is Rest** (1270-1274): the voice is force-closed —
```cpp
v.gs.gateHeld = false; v.gsStep.gateHeld = false; v.participating = false;
```
**This is the "cannot sound when voice 1 rests" rule.** No poly draw is even consulted.

**V1 landing (Legato / LegatoMax / Tie)** (1278-1350) — Rule-2 CONSUME:
- Not participating (rested at the onset) → stays silent (1291-1293).
- Participating: `connect = v.gs.slurForward && (wasHeldPoly || hadPolyTail)` — its OWN
  commitment AND it is genuinely still sounding (1307-1308). `connect && isTie` →
  `extendHold` own pitch; `connect` → `slideNote` to its OWN newly drawn pitch (keeps the chain
  accent); else → **re-articulate** fresh (own pitch, own NEW accent draw, 1332-1338 — a
  re-struck note is not stuck with the chain's opening accent). Then re-roll its forward
  commitment for the next landing (1343-1349).

**V1 MidNote** (1352-1388): the voice follows V1's hold only while its own armed window is open:
- V1 slid (Legato/LegatoMax) and `gs.gateHeld && wasHeldPoly` → voice draws its OWN pitch and
  slides (1355-1366) — it tracks V1's articulation SHAPE, never V1's notes.
- V1 tied → voice `extendHold`s its own pitch (1367-1370).
- Plain MidNote → `v.gs.gateHeld = (gatePulseRemain >= 0) || (holdRemain > 0.0001f)` (1381) —
  the guard that keeps a length-clamped voice's early release honest (re-opening a closed gate
  here would produce false teal continuations at the next landing).
- V1 gate low OR the voice opted out → closed (1383-1387).

**Clock-mode containment summary**: onset permission (only at V1 onsets) + V1-rest close +
length clamp to V1's event grid + hold-follow only inside V1's gate. The voice's gate width in
clock mode is its OWN (clamped) note length, armed at the V1 onset.

### 4.3 The chain latch — `participating`

The one poly-specific piece of state with no mono analogue (PolyVoice comment, 59-66): latched
TRUE when the voice PLAYED at the mono chain onset, held for the chain's life, cleared at each
new onset re-decision and when V1 rests. It — not the gate — decides whether a landing belongs
to the voice: "a voice that opted out and let its short note close still reads
participating==true and re-articulates, whereas a rester reads false and stays silent."

### 4.4 VAR/LEG delegation (EAST_EXTRA_LANES §4d)

`varlegLocalEast_[16][2]` (SequencerEngine.hpp:402): default false = DELEGATE — the voice reads
V1's VAR/LEG position (`getVariationStepForVoice`/`getLegatoStepForVoice`, 1477-1497), so its
variation (note length) and slur-roll pattern MIRROR V1's per-step values (shared ghost rhythm:
"+1 correlation"). Local East (East expander per-voice toggle) → the voice reads its OWN LOR
window. Either way the THRESHOLD is the voice's own `variationProb`/`legatoProb`. Rest and
accent have no such delegation — they are per-voice lanes, always.

## 5. Gate mode (Mode B) and subgates

### 5.1 Plain gate mode — `executeModeB` (SequencerEngine.cpp:843-943)

- Onsets only on `gate1Rise` (or first-rise-from-reset, 866-869). `advancePlayhead` then the same
  draw feeder block as Mode A (885-889), then **note-length nullification**: `nvIdx = 6`
  (1/16 = exactly one step, 900) and the internal countdown is explicitly cleared AFTER
  `wasHeldMono`/`hadMonoTail` capture (932-933) — the note DURATION is Gate 1's width, and the
  clear defeats the MidNote swallow so rest/legato still decide at every rise.
- `executeStep` runs identically (rest/legato/accent all apply — the dispatch comment at
  MonsoonModeController.cpp:311: "In Mode B, variation and note length should have no impact on
  the gate. Only legato, rest, and accent apply." V1's `variationProb` is forced neutral 0.5,
  318). The poly cascade runs through the same `postExecute_` → `executePolyVoice` path, so
  §4.2 applies unchanged; every poly voice's `nvV` is also effectively the clamp floor.

### 5.2 The per-sample gate-state drive (IMPL 2b, mono) — Monsoon.cpp:1128-1196

While `modeSelect == 1 && runGateActive`, EVERY sample (outside the step edges):

```cpp
const bool isRest        = (engine.lastStepResult.decision == MonoDecision::Rest);
const bool ghostSounding = engine.ghostActive && input.ghostHigh;
const bool gapBridge     = engine.tieAcrossRests ? engine.gs.slurForward : prevGate1SchmittHigh;
const bool gateOpen      = !isRest && (gate1High || ghostSounding || gapBridge);
engine.gs.gateHeld     = gateOpen;
engine.gsStep.gateHeld = !isRest && (gate1High || ghostSounding);   // STEP never bridges
```
Closed gate also zeroes `holdRemain`/`gatePulseRemain` (1191-1196, Lantern parity). Rest wins
over everything (`!isRest` first); the gap bridge (tieAcrossRests) carries a committed slur
across structural gaps; the STEP mirror re-articulates at every gate. This sets V1's STATE —
every read path (GATE_OUTPUT, STEP, CV, Lantern, and the poly AND below) agrees by construction.

### 5.3 The three subgate edge streams — Monsoon.cpp:855-898 + executeModeBSubdivided

- **Gate 1 = main**: note events. Its rise is a note-START, its fall a note-END; edges OWN the
  boundary samples.
- **Gate 2 = ratchet** (`SUBGATE_RATCHET`): fires only IN-GATE (`inGate && gate2Rise`, 878) —
  sub-cells inside a main gate. Not variation-gated.
- **Gate 3 = ghost** (`SUBGATE_GHOST`): fires only IN-GAP, and one sample clear of the fall
  (`genuinelyInGap = !inGate && !prevGate1SchmittHigh`, 887-888) — the main gate owns its edge
  samples. **Variation-gated**: the ghost is a CANDIDATE — `r_vary >= variationProb` → no ghost
  (silent gap cell, executeModeBSubdivided 1022-1034); then `executeStep`'s rest roll may still
  silence it. `ghostActive` latches a played ghost until a main/ratchet onset (1036).
- All three streams advance the playhead and run the SAME `executeStep` — legato flows across
  intra-gate, inter-gate AND ghost↔main boundaries uniformly through wasHeld/prevSlur (the
  leading-edge model composes; the spec's TRAP — no forced re-articulation at coincident edges).
  Ghost→main tie-through-rise is EMERGENT (Monsoon.cpp:1155-1164): a ghost still high at the
  rise keeps `gateHeld` true via `ghostSounding`, so `executeStep` reads `wasHeld=true` and the
  ghost's own slurForward decides Legato/Tie vs fresh NewNote.
- Mode B nullification applies here too: `nvIdx = 6`, countdowns cleared (995, 1014-1015).

### 5.4 Poly gate-width follow (IMPL 2b, poly) — Monsoon.cpp:1198-1213 — THE containment in gate mode

After each stepped poly execution, the module latches each voice's sounding decision:
```cpp
polyVoiceActive[i] = engine.voices[...].gs.gateHeld;      // Monsoon.cpp:1009-1012
```
Then per sample:
```cpp
const bool vOpen = gateOpen && polyVoiceActive[i];
engine.voices[vs].gs.gateHeld = vOpen;
if (!vOpen) { holdRemain = 0.f; gatePulseRemain = -1; }
```
**The poly gate is the logical AND of the V1 envelope (`gateOpen` — Gate-1 width / ghost /
slur bridge, rest-punched) and the voice's own latched play decision.** The voice's own rest
chooses to be silent INSIDE the envelope; it can never extend outside it. `gsStep` is left to
`executePolyVoice`'s per-onset retrigger (STEP re-articulates by design). This is the
"subtractive intersection" in its purest form — one AND per voice per sample.

### 5.5 Output rendering (shared by all modes)

`MonsoonOutputGenerator.cpp:39-92` precomputes per voice ONCE per sample (double-advance fix):
`vg = voices[vs].gs.process(sampleTime)`; poly accent out = `voices[vs].accented && vg > 5`
(each voice's OWN accent gate, gated by actually sounding); poly SLEG = `slurMember ? vgStep : 0`.
Straits poly cables ch0 = V1 duplicated from the mono path, ch1..15 = V2..V16 (94-127); Changi
T1/T2 mirror per-voice (129-162). Mono: `generateOutputs` (165-202) emits GATE / CV / STEP /
SLEG / ACCENT. Mute/inactive voices freeze (no `process()` call) at 0 V.

## 6. The five containment mechanisms (the thing to generalise)

| # | Mechanism | Clock/phase | Gate mode | Code anchor |
|---|---|---|---|---|
| C1 | **Onset permission** — poly may only start at a V1 onset | `monoGateStart` gate | same + gate1Rise stream | SequencerEngine.cpp:1128-1131 |
| C2 | **V1-rest close** — V1 rests → every voice force-closed, no draws consulted | 1270-1274 | `!isRest` term of `gateOpen` (mono) ANDed via `vOpen` (poly) | SequencerEngine.cpp:1270; Monsoon.cpp:1170,1206 |
| C3 | **Length clamp** — voice hold ≤ V1's next event | `nvIdxForVoice` max-clamp | trivially true (nvIdx=6, envelope drives width) | SequencerEngine.cpp:1499-1508 |
| C4 | **Hold-follow** — mid-gate, voice holds only inside V1's hold + own armed window | MidNote branch 1352-1388 | `gateOpen` per-sample AND | SequencerEngine.cpp:1381; Monsoon.cpp:1205-1213 |
| C5 | **Envelope intersection** (gate mode explicit form) | implicit (C1+C2+C4) | `vOpen = gateOpen && polyVoiceActive[i]` | Monsoon.cpp:1206 |

The asymmetry Rodney describes falls out exactly: a voice CAN rest when V1 does (C2 closes it;
also its own rest draw may silence it inside V1's envelope) but CANNOT sound when V1 rests
(C2/C5 — there is no term that can reopen a closed envelope; `polyVoiceActive` only ever
restricts, and the voice's own draws are only consulted inside C1's permission points).

## 7. Generalisation to Cantonment forests — the modularisation plan

### 7.1 Target algebra

Replace "the mono envelope" with a per-voice ENVELOPE SET defined by the containment forest:

```
E(v) = Own(v)  ∧  ∧_{u ∈ parents(v)} E(u)          (multi-parent = INTERSECTION)
```
- `Own(v)` = the voice's own sounding decision (its rest draw inside the permission points —
  exactly today's `polyVoiceActive` / the clock-mode armed window).
- `parents(v)` = `{u : bit u set in containmentParents[v]}` — already staged every block
  (PatternEngine.hpp:285, MonsoonSandsManager.cpp:91-97), currently unread.
- Nesting is FREE: the ∧ over parents is transitively closed through the DAG (v in a's forest,
  a in root's → v's envelope ⊆ a's ⊆ root's). Acyclicity (the ContainmentGraph invariant,
  CI-marched on 600 seeds) is what makes the recursion well-founded.
- V1 containment is the degenerate case `parents(v) = {0}` for all v — today's behaviour is the
  single-parent instance of the algebra. R2 (disconnected vertices valid) gives
  `parents(v) = ∅` = a FREE voice (today's algebra cannot express this; see §8 D2).

### 7.2 Where each mechanism generalises

- **C1 (onset permission)** → a voice's permission points are the onsets of ALL its containers:
  re-decide (rest/pitch/accent/lead rolls) at any edge where every container is sounding and at
  least one container STARTS. Generalisation of `monoGateStart`: replace the single
  `lastStepResult` read with "the set of container verdicts this edge" (see D4).
- **C2 (rest close)** → close v when ANY container rests (the ∧ already says this). Generalises
  the mono-Rest branch to a loop over parents.
- **C3 (length clamp)** → clamp to the SHORTEST container window: `nv_v = max(nv_own,
  max_{u∈parents} nv_u)` in NOTE_VALUES indexing (higher = shorter). Today: `max(nv, V1's)`.
- **C4 (hold-follow)** → MidNote follow becomes "follow the SHORTEST still-sounding container";
  with multi-parent the ∧ of gates replaces `gs.gateHeld` (mono's).
- **C5 (envelope intersection)** → `vOpen = (⋀_{u∈parents} envelope(u)) && polyVoiceActive[v]`,
  where `envelope(u)` is u's OWN final gate state (`voices[u].gs.gateHeld` post-drive, computed
  in voice order — the DAG's topological order; acyclicity guarantees parents resolve first).
  Monsoon.cpp:1205-1213's loop becomes containment-driven: same AND shape, parents instead of
  the implicit V1.

### 7.3 The refactor seams (modularisation)

1. **ParentView extraction** (engine layer): `executePolyVoice` reads V1 through exactly four
   scalars — `lastStepResult.decision`, `lastStepResult.nvIdx`, `wasHeldMono`/`hadMonoTail`,
   `gs.gateHeld`. Extract a `struct ParentView { MonoDecision decision; int nvIdx; bool
   gateHeld, wasHeld, hadTail; }` + `ParentView parentView(u)`; mono keeps working by passing
   `{V1's}`. All five C-mechanisms then read `parents(v)` through it. The pure cascade body
   (rest/legato/accent/pitch) does not change — the permission scaffolding does.
2. **Envelope staging** (module layer): the publish already stages `containmentParents` every
   block; add a per-sample ordering pass that walks voices in topological order driving C5.
   `polyVoiceActive[]` (Monsoon.cpp:1009) becomes per-parent-pair generalised (or kept as the
   Own(v) latch).
3. **Executor neutrality**: `executeModeBSubdivided`/IMPL 2b are already mono-shaped but
   single-parent hardwired only at 1205-1213 and 1270-1274 — the two loops to generalise. The
   ghost machinery needs ONE ruling (D5) on whose variation gates a ghost when containers
   disagree.
4. **What does NOT change**: `executeStep` (V1's own cascade), GateState, the LOR/warp/spread
   plumbing, the transforms/pending/trajectory stack (already graph-generic and CI-marched),
   the output rendering (it renders whatever `gs.gateHeld` says).

### 7.4 Testability

- The graph layer is already proven: ContainmentGraph invariants + 600-seed closure marches
  (test_containment_transforms 94, test_containment_pending 69 incl. P9, test_containment_module
  473 incl. S8) — the envelope algebra is a second pure layer over the same DAG: property test
  "E(v) ⊆ E(u) for every u ∈ parents(v), at every edge, on seeded random forests".
- Backward-compat pin: with `parents(v) = {0} ∀v` the generalised engine must be byte-identical
  to today (the R2 → legacy mapping question, D2). Existing suites that already pin the V1
  semantics: test_per_voice_articulation, test_legato_leading_edge, test_poly_slur_roll,
  test_rule2_consume / test_rule2_integration, test_note_length, test_subgate,

- **D1 — multi-parent envelope semantics**: intersection (all containers sounding — matches the
  multi-pin row = intersection language and CA pin precedent) vs union vs majority. Recommended:
  intersection.
- **D2 — the zero-row mapping**: today ALL poly voices are implicitly contained in V1. Under
  the generalised algebra, `parents(v) = ∅` (R2 default, all-zeros publish) = FREE voices —
  i.e. adopting the algebra as-is CHANGES the default sound (voices detach from V1). Options:
  (a) behaviour break is intended (Cantonment is the new truth; legacy patches keep V1
  containment by CONTAINMENT-module state, all-pins-to-V1 as the migration default), or
  (b) `∅` falls back to legacy follow-V1 (compat, but R2's "disconnected = valid free voice"
  becomes unexpressable). Recommended: (a) with an explicit migration default of
  "all-contained-in-V1" authored into the module's default graph.
- **D3 — onset permission under multi-parent** (C1 generalisation): re-decide only when ALL
  containers start (rare, rhythm-locking) vs at ANY container onset while all envelopes are
  open (musically the useful one). Recommended: any-container-onset + all-open.
- **D4 — decision authority for gate TYPE at a poly onset** (trigger vs slide) when multiple
  containers land differently: follow the EARLIEST container's verdict? the FIRST in voice
  order? Recommended: the topologically-first sounding container (deterministic, matches "the
  voice tracks the shape of its container chain").
- **D5 — ghost ownership under a forest**: today the mono VAR gates ghosts. Generalised: each
  voice's ghost candidacy gates on its OWN variation (already per-voice) — but whose envelope
  hosts the ghost (a ghost is an in-gap event of the container's gate)? Recommended: a voice's
  ghost exists only inside the intersection envelope of its containers (consistent with C5).
- **D6 — phasing scope**: keep this generalisation engine-internal (envelope algebra over the
  existing per-voice gs) vs also generalising the LOR windows per container edge. Recommended:
  engine-internal first; LOR-per-edge is a later, separate step.
