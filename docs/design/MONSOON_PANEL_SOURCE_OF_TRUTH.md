# Monsoon panel: which file is LIVE (resolving CC's confusion)

CC has been confused about the Monsoon panel because the repo has ~14 Monsoon panel SVGs and several
generators that DISAGREE with each other in their own headers. This pins the truth.

## The LIVE panel (what the module actually loads)
MonsoonWidget.cpp:540-541 loads:
- res/panels/Monsoon_panel_dark_monsoon.svg
- res/panels/Monsoon_panel_light_monsoon.svg
THESE TWO are the live panels. Nothing else is loaded by the module.

## How the live panel is actually PRODUCED (the confusing part)
It is NOT "generated by one script" and NOT "purely hand-authored" -- it is a HAND-AUTHORED BASE that a
CHAIN of embed/modify scripts post-processes IN PLACE. The scripts that touch the live _monsoon.svg:
- embed_monsoon.py (emits param/port/light markers)  <- the main embed
- embed_cluster_art.py, fader_level_markers.py, mode_column.py, recolour_family_peranakan.py,
  supertree.py (further in-place modifications: art, fader ticks, mode column, peranakan recolour, trees)
So the pipeline is: hand-authored _monsoon.svg base -> embed_monsoon.py + the modify scripts -> the live
_monsoon.svg. To change the live panel you edit the base and/or these embed/modify scripts, then re-run
them against _monsoon.svg.

## The RED HERRINGS (not loaded -- ignore for live changes)
- **gen_monsoon.py** -- a PARALLEL from-scratch regeneration effort. Its header claims it "Replaces the
  hand-authored _monsoon.svg" -- but that replacement has NOT been adopted; the module does NOT load
  gen_monsoon.py's output. This is the main source of CC's confusion: the header says "replaces" but it
  hasn't. Do NOT edit gen_monsoon.py expecting the live panel to change.
- **gen_monsoon_clean.py** -- its header even CONTRADICTS gen_monsoon.py, calling the _monsoon.svg files
  "the richer 568-element hand-tuned" panels. Another parallel effort.
- gen_monsoon_components.py, degradient_monsoon.py -- helpers/experiments.
- SVG variants NOT loaded: Monsoon_panel_{dark,light}_GENERATED.svg, Monsoon_peranakan_{dark,light}.svg,
  Monsoon_Clean_40HP.svg, Monsoon_Main_40HP.svg, Monsoon_panel_expanded_{dark,light}.svg, plain
  Monsoon_panel_{dark,light}.svg. All are iterations/intermediates. Only _*_monsoon.svg is live.

## For CC: how to change the live Monsoon panel
1. The live files are Monsoon_panel_{dark,light}_monsoon.svg (MonsoonWidget.cpp:540-541).
2. They are produced by the hand-base + embed_monsoon.py + the modify scripts (above), NOT gen_monsoon.py.
3. To add/modify a panel element (e.g. the tonic indicator, IF Monsoon scale-authoring is built):
   add it to the appropriate embed/modify script (likely embed_monsoon.py for a per-degree marker, or a
   small new modify script), run it against _monsoon.svg, confirm MonsoonWidget still loads the same path.
4. Do NOT touch gen_monsoon.py / gen_monsoon_clean.py for live changes -- they are not adopted.
5. CLEANUP (optional, reduces future confusion): decide whether gen_monsoon.py is meant to eventually
   replace the hand-base pipeline. If YES, adopt it (point MonsoonWidget at its output, verify parity,
   delete the dead variants). If NO, delete gen_monsoon.py + gen_monsoon_clean.py + the unused SVG
   variants so only the live pipeline remains. Right now the contradiction between the two generators'
   headers is the confusion; resolving it (adopt one, delete the other) prevents recurrence.

## Bearing on the tonic-indicator work
If Monsoon scale-authoring + the tonic indicator get built (TONIC_TRANSPOSE_BUILD_BRIEF), the tonic
marker must be added to the LIVE pipeline (embed/modify scripts -> _monsoon.svg), NOT to gen_monsoon.py
-- a marker added to gen_monsoon.py would never appear, because that output isn't loaded. This is
exactly the wasted-work trap the confusion causes.
